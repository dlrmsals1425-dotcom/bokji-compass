# 팀원용 음성 실행 안내

음성 기능이 포함된 `jinwoo` 브랜치를 받거나 해당 변경을 작업 브랜치에 반영한 뒤, 각 팀원 PC에서 앱을 실행한다. 코드는 Git으로 공유하고 OpenAI API 키는 팀에서 별도로 전달한다. 공유받은 키를 쓰면 그 키 소유자의 API 사용량으로 처리되며, 본인 키를 쓰면 본인 계정에서 처리된다.

## 코딩 에이전트에게 보낼 문장

> AGENTS.md와 docs/TEAM_VOICE_SETUP.md를 읽고, 이 프로젝트를 음성 기능까지 로컬로 실행해 줘. OPENAI_API_KEY가 없으면 나에게 설정을 요청하고, 이미 있으면 그대로 사용해 줘. 키는 .env.local에서만 사용하고 Git에 올리지 마.

루트 `AGENTS.md`에 **키 확인 → 없을 때 요청 → 로컬 설정 사용 → 서버 실행·확인** 절차가 있다. `CLAUDE.md`도 이를 참조한다. 사용하는 에이전트가 이 파일들을 자동으로 읽지 않으면 위 문장을 직접 전달한다. 이 안내는 에이전트 작업 규칙이며 `npm` 명령 자체에 키 입력창을 추가한 것은 아니다.

## 처음 한 번 설정

1. 코딩 에이전트가 키를 요청하면 팀에서 별도로 받은 OpenAI 키 또는 본인 키를 준비한다.
2. `package.json`이 있는 프로젝트 루트에 `.env.local`을 만들고 다음 항목에 실제 키를 넣는다. 기존 파일이 있으면 다른 설정은 유지하고 이 항목만 추가·수정한다. 파일명에 `.txt`를 붙이지 않는다.

   ```env
   OPENAI_API_KEY=여기에_전달받은_키
   ```

3. 키는 파일에 직접 넣거나 코딩 도구의 비밀 입력 기능을 사용하고, 에이전트에는 **설정했음**이라고 알려준다. 에이전트가 서버를 시작하거나 재시작한다.

`.env.local`은 Git에서 제외된다. 키 파일과 키가 보이는 화면은 PR·이슈·커밋에 올리지 않는다. `DATA_GO_KR_SERVICE_KEY`는 데이터 재수집용이므로 기존 앱과 음성 기능만 실행할 때는 필요 없다. Python·Whisper 설치도 필요 없다.

## 실행과 확인

프로젝트 폴더에서 실행한다. 아래는 Windows PowerShell에서 검증한 프로덕션 실행 명령이다.

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd run start -- -p 3220 -H 127.0.0.1
```

macOS/Linux에서는 `npm.cmd` 대신 `npm`을 사용한다. 개발 중에는 `npm run dev`로 실행하고 터미널에 표시된 주소의 `/situation`을 연다.

브라우저에서 [말로 찾기](http://127.0.0.1:3220/situation)를 열어 동의 → 음성 입력 시작 → 말하기 완료 → 문장 확인 → 입력칸에 넣기를 사용한다. 각 팀원이 자신의 PC에서 열어야 하며 `127.0.0.1`은 다른 팀원의 서버 주소가 아니다.

`GET /api/voice/transcribe`가 `available: true`를 반환하면 키 설정은 읽힌 상태다. 실제 키 유효성·잔액·음성 인식은 음성을 전송해야 확인할 수 있으며 API 사용량이 발생한다. 구현과 검증 범위는 [VOICE.md](VOICE.md)를 따른다.

## 이후 코드 갱신

- pull·merge 후에도 기존 `.env.local`을 유지한다. 키를 매번 다시 받을 필요는 없다.
- 개발 서버를 재시작한다. 프로덕션 방식이면 기존 서버를 종료하고 `npm run build` 후 다시 시작한다. 의존성이 바뀌었으면 먼저 `npm ci`를 실행한다.
- 키가 폐기·교체되면 해당 항목만 새 값으로 바꾸고 서버를 재시작한다. 설정된 키를 확인한다며 키 자체를 출력할 필요는 없다.
- 키 없이도 직접 입력 기능은 이용할 수 있지만 음성 기능은 연결되지 않는다.
